# Swayframe V0.4
# Agent-Guided Creation & Intelligent Compositing
# Revised Implementation Specification

你现在开始对 Swayframe 的 AI Agent 创作系统
进行一次核心架构与交互升级。

本轮开发重点：

Agent Planning
Task Decomposition
Capability Discovery
Intelligent Tool Selection
Graph Construction
Node-Level Prompt Editing
Branch-Level Modification
Change Scope Protection
Capability Reuse

本次任务不是：

增加更多 AI 按钮。

不是：

开发第二套 Compositing Graph。

不是：

让 Agent 更频繁地编写 Shader。

而是：

让 Agent 真正理解 Swayframe 的创作结构，
能够根据复杂需求制定合理方案，
智能使用软件已有能力，
并允许创作者对生成结果进行精确、局部、可控的修改。

============================================================
一、产品核心目标
============================================================

Swayframe 是一款：

Human-first, AI-native
Motion Design & Compositing Software。

传统操作模式必须完整保留。

用户不使用 AI，
依然可以通过：

Canvas
Inspector
Timeline
Motion Curve
Compositing Graph

完成专业创作。

AI Agent 的角色不是：

模仿人类不停点击按钮。

而是：

理解需求
→
分析现有工程
→
拆解任务
→
查询已有能力
→
选择最合理的实现方式
→
执行修改
→
检查结果
→
将控制权交还给用户。

Agent 应具备三个能力层级：

L1 — OPERATOR

调用原生编辑命令。

L2 — COMPOSER

组合现有图层、动画、节点和效果。

L3 — TOOLMAKER

当现有能力无法满足需求时，
调用 Effect Forge 创造程序化效果。

本轮优先完善：

L1 + L2。

L3 复用现有 V0.3 架构，
不重新开发一套 Effect Forge。

============================================================
二、本轮必须解决的五个问题
============================================================

问题一：

Agent 不理解复杂任务的结构。

例如：

用户希望制作：

“蓝色动态渐变背景，
带有柔和噪声和发光，
标题从下方向上弹入。”

Agent 可能把所有东西作为一个任务执行，
导致结构混乱。

必须能够拆分：

背景生成
视觉处理
文字对象
运动动画
最终合成。

------------------------------------------------------------

问题二：

Agent 不知道什么时候使用已有能力。

例如：

软件已经存在 Radial Gradient，
却用多个图层和 Gaussian Blur 模拟。

或者：

已有 Gaussian Blur，
却重新生成一个模糊 Shader。

必须建立：

Capability Discovery
+
Reuse-First Strategy。

------------------------------------------------------------

问题三：

Agent 不理解现有工程。

用户希望修改背景颜色，
Agent 却重新创建整套背景结构。

必须能够：

Inspect Existing Scene

Inspect Existing Graph

Locate Relevant Object

Identify Related Parameters

Modify Existing Content。

------------------------------------------------------------

问题四：

Agent 无法限制修改范围。

用户只希望修改一个节点，
Agent 却改变整个 Composition。

必须实现：

Parameter Scope
Node Scope
Branch Scope
Composition Scope。

------------------------------------------------------------

问题五：

Agent 创建的结构不便于用户继续编辑。

必须保证：

生成的内容能够在：

Canvas
Inspector
Timeline
Compositing Graph

中正常编辑。

禁止：

将复杂作品简单转换成不可编辑的最终图片。

============================================================
五、Agent 必须先理解任务，再执行
============================================================

从现在开始：

Agent 收到创作需求后，
不能立即开始创建节点。

必须先运行：

Intent Analysis
+
Project Inspection
+
Task Decomposition。

例如：

用户：

“创建一个科技感标题动画，
具有深蓝色径向渐变背景，
轻微流动噪声，
标题从下方弹入。”

Agent 应生成如下结构化任务：

TASK 1

Create Gradient Background

TASK 2

Create Noise Treatment

TASK 3

Apply Glow

TASK 4

Create Text Layer

TASK 5

Animate Text Position

TASK 6

Apply Motion Curve

TASK 7

Composite Result

并为每项任务指定：

Execution Domain。

例如：

TASK 1 → Generator / Fill

TASK 2 → Effect Engine / Graph

TASK 3 → Effect Engine

TASK 4 → Scene / Text Layer

TASK 5 → Timeline

TASK 6 → Motion Curve

TASK 7 → Compositing Graph / Renderer

注意：

Task Decomposition 不等于 Node Decomposition。

不是每项任务都需要对应一个节点。

============================================================
六、建立 Agent Planner
============================================================

建立或扩展：

Agent Planner。

参考结构：

interface CreationPlan {
  id: string;

  goal: string;

  targetCompositionId: string;

  scope: ExecutionScope;

  tasks: CreationTask[];

  dependencies: TaskDependency[];

  proposedChanges: ProposedChange[];

  status: PlanStatus;
}

interface CreationTask {
  id: string;

  description: string;

  executionDomain:
    | "scene"
    | "canvas"
    | "property"
    | "animation"
    | "compositing"
    | "generation"
    | "effect-forge";

  strategy:
    | "modify-existing"
    | "reuse"
    | "compose"
    | "generate"
    | "forge";

  capabilityId?: string;

  targetIds?: string[];

  dependencies?: string[];
}

以上为参考类型。

具体实现必须复用仓库已有数据模型。

不能因为示例接口不同，
重新建立不兼容的第二套系统。

Plan 必须使用结构化数据，
并通过 Schema Validation。

不能直接执行模型输出的任意 JSON。

============================================================
八、Agent 的实现选择策略
============================================================

正式定义以下优先级：

1. MODIFY EXISTING

2. REUSE EXISTING CAPABILITY

3. COMPOSE EXISTING CAPABILITIES

4. GENERATIVE OPERATION

5. EFFECT FORGE

但需要综合评估：

Semantic Accuracy
Visual Fidelity
Editability
Performance
Graph Complexity
Execution Cost
Portability。

例如：

用户：

“把背景调成紫色。”

如果现有 Gradient Node 能通过 Color Stops 修改：

必须优先修改已有节点。

禁止：

直接创建新的背景图层。

------------------------------------------------------------

用户：

“添加高斯模糊。”

如果存在 Gaussian Blur：

直接使用。

禁止：

重新生成模糊 Shader。

------------------------------------------------------------

用户：

“创建复杂液态折射。”

如果现有 Distortion、
Noise 和 Refraction 能够准确实现：

优先组合已有能力。

只有现有能力确实不足，
才调用 Effect Forge。

例如：

Command System。

禁止 Agent：

直接修改 Scene JSON。

============================================================
十一、Prompt-to-Composition
============================================================

用户的完整创作需求，
不应该全部转换为节点。

例如：

“制作科技感标题动画。”

最终工程可能包含：

SCENE

Background Layer
Text Layer

TIMELINE

Text Position Keyframes
Opacity Keyframes
Motion Curve

COMPOSITING GRAPH

Gradient
Noise
Glow
Merge

这些内容必须共同组成：

同一个可编辑工程。

禁止：

Text Animation 被转换成大量无意义节点。

禁止：

Compositing Graph 重新实现一套 Timeline。

至少能够查询：

哪些节点已经存在。

哪些节点能够复用。

哪些节点属于目标分支。

哪些节点不应被修改。

============================================================
十三、实现 Node-Level Prompt
============================================================

这是本轮重点功能。

当用户选中一个节点后，

Inspector 提供：

Modify with AI。

用户输入：

“让这个模糊更明显。”

Agent：

读取当前 Gaussian Blur。

检查 Radius。

生成：

Parameter Change Proposal。

例如：

Radius:
20 → 35

不得：

创建第二个 Blur Node。

不得：

重新生成 Shader。

不得：

修改整个 Graph。

------------------------------------------------------------

对于 Radial Gradient：

用户输入：

“让蓝色中心更亮一些。”

Agent 应优先调整：

Color Stops
Radius
Center

等已有参数。

而不是：

创建多个新图层。

============================================================
十四、Node-Level Prompt 的默认权限
============================================================

用户从某个节点发起 AI 修改时：

默认：

PARAMETER_ONLY。

如果参数不足：

可以提出：

SELECTED_NODE

级别的修改方案。

如果当前节点无法单独完成：

可以建议：

SELECTED_BRANCH。

但是：

Agent 不能自行扩大修改范围。

扩大 Scope 时：

必须向用户说明：

为什么需要扩大。

哪些节点将受到影响。

未经接受：

不得修改其他节点。

============================================================
十五、建立 Branch-Level Prompt
============================================================

这是本轮另一个最高优先级功能。

用户能够选择：

某个节点分支。

然后输入：

“让背景变成紫色，
降低发光强度，
但不要修改文字动画。”

Agent 必须：

1. 识别背景分支。

2. 定位 Gradient Node。

3. 定位 Glow Node。

4. 修改 Color Stops。

5. 修改 Glow Intensity。

6. 保留 Noise Node。

7. 保留 Text Layer。

8. 保留文字 Keyframes。

9. 保留 Motion Curve。

10. 保留其他无关内容。

如果无法可靠定位背景分支：

不得猜测后直接大范围修改。

应提供候选对象或要求用户选择。

============================================================
十六、建立修改范围保护
============================================================

定义：

PARAMETER_ONLY

SELECTED_NODE

SELECTED_BRANCH

FULL_COMPOSITION

并建立：

Scope Validator。

不能只在 Prompt 中写：

“不要修改其他内容”。

必须由代码检查：

拟修改对象 ID

拟删除对象 ID

拟新增连接

受影响的分支边界

是否超出 Scope。

如果超出：

Reject Plan

或：

Request Scope Expansion。

尤其注意：

修改一个分支的输出，
可能影响最终合成画面。

这属于预期的下游渲染变化。

但不意味着：

Agent 可以修改下游无关节点的参数和结构。

必须区分：

Rendering Dependency

和：

Mutation Permission。

============================================================
十七、建立 Graph Change Proposal
============================================================

对已有工程的 AI 修改，
先生成结构化 Proposal。

Proposal 至少包含：

Modified Objects

Created Nodes

Deleted Nodes

Modified Nodes

Removed Connections

Unchanged Scope

Warnings

例如：

Target:

Background Branch

Changes:

Gradient Color Stop:
Blue → Purple

Glow Intensity:
1.5 → 0.8

Preserved:

Text Layer
Text Keyframes
Motion Curve
Camera
Other Branches

提供：

Preview
Accept
Reject。

正式提交必须：

一次 Transaction

支持 Undo / Redo。

预览不得直接污染正式工程状态。

============================================================
十八、建立最小修改原则
============================================================

正式引入：

MINIMUM NECESSARY CHANGE。

例如：

只需要修改两个参数，
就不应该：

创建四个节点。

只需要修改已有 Node，
就不应该：

删除原 Node 再创建新 Node。

只需要修改背景分支，
就不应该：

重新构建整个 Composition。

只需要创建关键帧，
就不应该：

创建复杂 Motion Graph。

Agent Planner 应评估：

Node Count Increase

New Layer Count

Redundant Processing

Affected Object Count

Execution Cost

并优先选择：

满足需求且结构简单的方案。

============================================================
十九、AI Graph 自动布局
============================================================

Agent 自动生成的 Graph 必须易于理解。

遵循：

Left-to-right Processing Flow。

自动布局：

Sources
→
Processing
→
Composite
→
Output。

要求：

避免节点重叠。

减少连线交叉。

多分支之间保持空间分隔。

使用语义化节点名称。

复杂分支允许折叠或分组。

但不要为了美观：

把所有节点封装成不可检查的黑盒。

优先复用现有 Graph Layout Engine。
