你现在需要在当前 Motion Design 软件中新增一个核心动画模块：

======================================================================
Motion Curve System
专业速度曲线 / Easing 控制系统
======================================================================

它可以参考 After Effects 中 Flow、Pro Motion Curves、Motion Pro 一类工具的交互思想，
但不要复制任何第三方插件代码、UI 美术资源或专有实现。

目标不是制作一个外挂插件，而是把“专业动画速度曲线控制”变成当前软件原生动画系统的一部分。

该系统未来还需要被：

Human User
AI Motion Intelligence
AI Agent

共同调用，因此必须具有明确的数据模型和 API。

在开始开发之前：

1. 阅读当前 Property System
2. 阅读 Keyframe Model
3. 阅读 Animation Evaluation
4. 阅读 Timeline
5. 阅读 Graph Editor
6. 阅读 Command / Transaction / Undo 系统

不得另外创建一套和现有关键帧系统互不兼容的动画系统。

======================================================================
一、核心设计思想
======================================================================

本系统分为两个层次：

A. Motion Curve Editor
面向绝大多数用户的标准化 Easing 编辑器。

B. Speed Graph
面向专业用户的真实速度曲线编辑器。

不要把二者混为一谈。

Motion Curve Editor 使用：

Normalized Time
0 → 1

Normalized Progress
0 → 1

形成一条标准化 Cubic Bezier Easing Curve。

例如：

P0 = (0, 0)
P1 = (x1, y1)
P2 = (x2, y2)
P3 = (1, 1)

默认 Linear：

cubic-bezier(0, 0, 1, 1)

典型 Ease：

cubic-bezier(...)

曲线本身不保存：

像素位置
Scale 数值
Rotation 数值

而只描述：

“在两个关键帧之间，动画进度如何随时间变化。”

因此同一条 Motion Curve 可以应用到：

Position
Scale
Rotation
Opacity
Color
Effect Parameter
Camera
Mask Parameter

等不同 Property。

======================================================================
二、核心数学模型
======================================================================

两个关键帧：

K0:
time = t0
value = v0

K1:
time = t1
value = v1

首先得到标准化时间：

u = (t - t0) / (t1 - t0)

其中：

0 <= u <= 1

然后通过 Motion Curve：

p = easing(u)

得到：

0~1 的动画进度 p。

最终：

value(t) = interpolate(v0, v1, p)

对于 Number：

v = v0 + (v1 - v0) * p

对于 Vec2：

x = x0 + (x1 - x0) * p
y = y0 + (y1 - y0) * p

对于 Vec3：

同理。

Color：

逐通道插值，具体颜色空间沿用项目现有 Color System。

注意：

Temporal Easing 和 Spatial Path 必须分开。

例如 Position：

Motion Curve
负责：

物体什么时候快
什么时候慢

Spatial Path
负责：

物体往哪里走。

修改速度曲线不应该改变运动路径的几何形状。

======================================================================
三、Motion Curve 数据结构
======================================================================

建立独立、可序列化的数据模型。

建议类似：

interface CubicBezierCurve {
    type: "cubic-bezier";

    x1: number;
    y1: number;

    x2: number;
    y2: number;
}

同时预留：

type MotionCurve =
    | LinearCurve
    | CubicBezierCurve
    | SpringCurve
    | BounceCurve
    | CustomCurve;

第一阶段重点实现：

Linear
Cubic Bezier

不要为了 Spring/Bounce 延迟核心系统。

但是接口必须能够未来增加。

======================================================================
四、Curve 应属于“关键帧区间”
======================================================================

必须认真处理 Curve 的归属。

一条 Easing Curve 本质上控制：

Keyframe A → Keyframe B

之间的时间插值。

因此不要简单把曲线作为：

Property.curve

否则多个 Keyframe 无法拥有不同动画节奏。

设计：

Keyframe Segment

或 equivalent representation：

Keyframe A
      ↓
Interpolation Segment
      ↓
Keyframe B

Segment 中包含：

temporalInterpolation
curve

例如：

segment:
{
    fromKeyframeId,
    toKeyframeId,
    interpolation: "bezier",
    curve: {
        x1,
        y1,
        x2,
        y2
    }
}

如果现有架构已经使用：

outgoing interpolation
incoming interpolation

优先兼容当前模型，不要无意义重构。

======================================================================
六、Bezier 编辑约束
======================================================================

为了保证合法的 timing function：

默认限制：

0 <= x1 <= 1
0 <= x2 <= 1

Y：

允许超过：

0~1

例如：

y > 1

用于：

Overshoot

y < 0

用于：

Anticipation

因此可以形成：

Back
Overshoot
Elastic-like

视觉效果。

但需要保证：

时间轴 X 方向保持可求值。

如果实现任意 Cubic Bezier 求逆：

需要根据 u 求参数 tBezier：

Bx(tBezier) = u

然后计算：

By(tBezier)

可使用：

Newton-Raphson

并提供：

Binary Search

作为数值稳定 fallback。

禁止粗暴使用：

BezierY(u)

代替真正的：

BezierY(BezierX^-1(u))

否则当：

x1 / x2 != 默认值

时 easing 会计算错误。

为 Cubic Bezier Solver 编写独立 Unit Tests。

======================================================================
八、应用模式
======================================================================

用户选中两个或多个关键帧后：

可以将 Curve 以三种模式应用：

Both
Out
In

Both：

同时设置选中动画区间的完整 easing。

Out：

主要修改离开第一个关键帧的 easing。

In：

主要修改进入第二个关键帧的 easing。

具体数据映射必须与当前 Keyframe Interpolation Model 一致。

如果架构不适合直接模拟 AE 的 incoming/outgoing velocity，
可以先在 MotionCurve Segment 层定义清晰语义，
再由 adapter 映射到 Speed Graph。

======================================================================
九、Reverse
======================================================================

实现：

Reverse Curve

例如：

Ease Out

反转为：

Ease In

数学上应真正反转 easing：

reverse(u) = 1 - easing(1 - u)

不要仅仅交换 preset 名称。

Curve Editor 必须立即显示反转后的结果。

======================================================================
十六、真正 Speed Graph
======================================================================

在专业 Graph Editor 中保留真正的：

Speed Graph

不要用 Motion Curve Editor 完全替代 Speed Graph。

对于 Number Property：

speed(t) = |dv/dt|

对于 Vec2 Position：

speed(t) = sqrt(
    dx/dt² +
    dy/dt²
)

正确写法：

sqrt(
    (dx/dt)^2 +
    (dy/dt)^2
)

对于 Vec3：

sqrt(
    (dx/dt)^2 +
    (dy/dt)^2 +
    (dz/dt)^2
)

单位可以显示：

px/s
deg/s
%/s

具体依据 Property。

Speed Graph UI：

X = Time
Y = Speed

显示：

Keyframe
Incoming Handle
Outgoing Handle

允许：

拖动 Y
改变速度

拖动 X
改变 Influence

二十八、验收案例
======================================================================

CASE 1

两个 Position Keyframe。

Linear：

物体匀速移动。

应用 Ease Out：

明显快速开始、缓慢结束。

CASE 2

Scale：

0 → 100

使用 Overshoot Curve：

动画超过 100 后回到最终状态。

如果当前 Cubic Bezier 单段模型无法真正产生回落，
不要伪造结果；
使用支持非单调 progress 的实现，
或把 Overshoot 交给未来 Spring/Back Curve 类型。

CASE 3

Opacity：

0 → 100

使用 Ease In：

开始变化缓慢，后期加速。

CASE 4

同时选中：

Position
Scale
Opacity

应用同一 Curve。

三个属性动画 timing 一致。

CASE 5

创建自定义 Curve。

Save Preset。

关闭重新打开软件。

Preset 仍然存在。

CASE 6

Apply Curve。

Undo。

恢复原 easing。

Redo。

重新应用。

CASE 7

修改 Curve Handle。

Canvas 动画 Preview 实时更新。

CASE 8

打开 Speed Graph。

显示真实速度变化。

Ease Out：

Speed Graph 应表现为：

速度较高
→
逐渐降低
→
趋近 0。

CASE 9

Position 使用曲线路径。

修改 Motion Curve。

运动路径几何形状不发生变化，

只改变沿路径运动的 timing。

这是非常重要的验收标准。
