你现在需要在当前 Swayframe 项目中新增一个核心高级模块：

======================================================================
Compositing Graph V0.1
节点式合成 / 图像处理流程系统
======================================================================

它可以参考 Nuke 等节点式合成软件的“节点 + 端口 + 连线 + 数据流”工作范式，
但不要复制任何商业软件代码、UI 资源或专有实现。

本模块的目标不是把 Swayframe 改造成 Nuke，
也不是让所有用户都必须使用节点。

Swayframe 仍然坚持：

Human-first
+
Layer / Timeline
+
Canvas Direct Manipulation
+
Inspector

作为主工作流。

Compositing Graph 是：

“复杂图像处理、合成、效果链和未来 AI 处理流程的高级可视化入口”。

======================================================================
一、最高设计原则
======================================================================

必须坚持以下原则：

1. 不替代现有 Layer / Timeline 工作流。

普通用户仍然可以完全不用 Node Graph，
完成：

Shape
Text
Image
Keyframe
Motion Curve
Mask
Effects
2.5D Animation

等工作。

2. Node Graph 是高级视图，不是第二套工程系统。

禁止建立：

Layer 数据
+
Graph 数据
+
Effect 数据

三套互不兼容状态。

3. Effect Stack 与 Compositing Graph 必须尽量共享同一份底层数据。

例如：

Inspector:

Exposure
Gaussian Blur
Glow

在 Graph 中应表现为：

Source
  ↓
Exposure
  ↓
Gaussian Blur
  ↓
Glow
  ↓
Output

用户在 Effect Stack 删除 Blur：

Graph 同步删除节点。

用户在 Graph 删除 Blur：

Effect Stack 同步更新。

不要保存两份状态。

4. 所有节点参数必须尽可能复用 Property<T>。

例如：

Blur.radius
Exposure.amount
Transform.position
Mask.feather

都应该可以：

添加 Keyframe
进入 Timeline
使用 Motion Curve
被 Agent 修改

5. 所有正式 Graph 修改必须经过 Command System。

Node Editor 不允许直接修改 Project JSON。

6. Compositing Graph 与内部 Render Graph 必须分离。

用户看到的是：

User Compositing Graph

内部 Renderer 使用的是：

Compiled Render Graph

不要把底层 GPU Pass 暴露给用户工程。

======================================================================
四、核心数据模型
======================================================================

建立清晰、可序列化的数据模型。

建议：

type NodeId = string;
type PortId = string;
type EdgeId = string;

interface CompositingGraph {
    id: string;

    nodes: CompositingNode[];

    edges: GraphEdge[];

    outputNodeId: NodeId;

    version: number;
}

interface CompositingNode {
    id: NodeId;

    type: CompositingNodeType;

    name: string;

    position: {
        x: number;
        y: number;
    };

    inputs: NodePort[];

    outputs: NodePort[];

    parameters: Record<
        string,
        Property<unknown>
    >;

    enabled: boolean;

    metadata?: NodeMetadata;
}

interface NodePort {
    id: PortId;

    name: string;

    direction: "input" | "output";

    dataType: NodeDataType;

    required?: boolean;
}

interface GraphEdge {
    id: EdgeId;

    fromNodeId: NodeId;
    fromPortId: PortId;

    toNodeId: NodeId;
    toPortId: PortId;
}

不要只设计：

fromNode
toNode

必须从第一天支持：

Port。

因为未来：

Merge
Mask
Generative
Depth
Track Matte

一定会出现多输入。

十、Merge Node
======================================================================

B

======================================================================
十一、Graph Edge Validation
======================================================================

建立连接验证。

禁止：

禁止：

十二、Graph Evaluation
======================================================================

Output

           Merge

B

======================================================================
五十九、最重要的产品原则
======================================================================

不要强迫普通用户学习 Nodes。

简单任务：

继续使用：

Canvas
Layer
Inspector
Timeline
Effects

复杂任务：

进入：

Compositing Graph。

Effect Stack 是：

Graph 的简化线性视图。

Graph 是：

复杂合成的高级结构化视图。

二者属于：

同一个工程。

======================================================================
最终目标
======================================================================

这次不是：

“做一个能拖方框连线的 Node UI”。

而是：

建立 Swayframe 第一代真正可执行的节点式合成系统。

Node：

必须真实参与 Renderer。

Parameter：

必须真实支持 Property / Keyframe。

Graph：

必须真实保存进 Project。

操作：

必须真实支持 Undo / Redo。

Effect Stack：

必须和 Graph 数据一致。

未来 Agent：

必须可以结构化控制 Graph。

完成后，Swayframe 应能够让用户：

普通动画继续使用 AE/Figma 式工作流，

复杂视觉处理切换到 Nuke 式 Graph 工作流，

而两种工作方式始终共享同一个底层工程体系。

Do not build a fake node editor.

Build a real compositing graph.
