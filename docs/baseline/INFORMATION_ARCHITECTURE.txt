你现在要对 Swayframe 进行一次“全局信息架构与功能入口重构”。

这不是一次普通 UI 美化任务。

当前最严重的问题不是颜色、圆角、字体，而是：

======================================================================
功能入口失控
======================================================================

当前 Swayframe 已经积累了大量功能，但出现以下问题：

- 同类功能分散在完全不同的位置；
- 高频功能被藏进二级甚至更深菜单；
- 低频功能反而长期占据一级界面；
- 同一个功能可能同时出现在多个不合理入口；
- Canvas、Scene、Inspector、Timeline、Graph、Menu 的职责混乱；
- 用户无法根据专业创作软件的常识预测“这个功能应该在哪里”；
- 新功能经常采用“实现一个功能 → 找个地方塞一个按钮”的方式接入；
- 功能虽然存在，但用户很难发现；
- 不同模块缺乏统一操作逻辑；
- 用户难以形成肌肉记忆。

本轮目标不是继续新增功能。

而是：

======================================================================
重新建立 Swayframe 的 Information Architecture
+
Interaction Architecture
+
Feature Placement Rules
======================================================================

并真正重新整理现有软件中的所有功能入口。

Whenever modifying user-facing UI or adding a new user-facing feature:

   - frequency
   - scope
   - context
   - primary user task

3. Consult FEATURE_LOCATION_MATRIX.md.

4. Reuse an existing entry point when possible.

5. Do not add a new permanent button unless DESIGN.md placement rules justify it.
